# Security Policy

## Supported Scope

Security fixes apply to the latest commit on `main` and the packaged extension generated by `npm run build`.

In scope:
- Manifest permissions, host permissions, CSP, and extension page security (`manifest.json`, `src/popup/`, `src/options/`)
- Service worker IPC sender checks, URL/endpoint allowlists, and remote selector config validation (`src/background.js`, `src/url-validator.js`, `src/remote-config.js`)
- Local storage privacy and secret handling for optional notification integrations (`src/storage.js`, `src/logger.js`, `src/notifications.js`)
- Content script injection boundaries (`src/providers/tab-helpers.js`, `src/content/`)

Out of scope:
- Vulnerabilities on third-party game stores themselves (`store.epicgames.com`, `store.steampowered.com`, etc.)
- Compromised user browser profiles or malicious third-party extensions installed alongside ClaimIt

## Design Guarantees

ClaimIt is built with the following security boundaries:
- Never requests, reads, or stores user passwords or session tokens; relies solely on existing browser sessions inside temporary background tabs.
- Enforces `content_security_policy` (`script-src 'self'; object-src 'none';`) with zero `innerHTML`/`eval`/`Function` usage.
- Restricts `chrome.runtime.onMessage` in the service worker and content scripts to own extension sender IDs (`sender.id === chrome.runtime.id`).
- Validates every tab target and store endpoint against strict HTTPS host allowlists (`src/url-validator.js`).
- Enforces strict schema allowlists, 512 KB size limits, and `redirect: 'error'` on remote selector configuration JSON and exchange-rate fetches.
- Redacts Telegram bot tokens and Discord webhook URL paths before storing logs or returning IPC errors.

## Reporting a Vulnerability

Please **do not open public GitHub issues** for unpatched security vulnerabilities.

Instead, report suspected vulnerabilities privately using one of the following channels:
1. **GitHub Security Advisories**: Open a private vulnerability report via the repository's **Security -> Advisories -> Report a vulnerability** page.
2. **Direct contact**: Contact the repository maintainer privately via the security contact address listed on the repository profile or security advisory page.

Please include:
- A clear description of the issue and affected file(s)
- Reproduction steps or a minimal proof of concept
- Any suggested remediation if known

### Response Timeline

- **Initial acknowledgement**: Within 72 hours of receiving a report
- **Assessment and triage**: Within 7 days
- **Fix and disclosure**: Critical or high-severity issues are prioritized for an immediate patch release, with coordinated public disclosure after a fix is available on `main`.
